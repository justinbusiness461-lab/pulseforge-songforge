## Universal product requirement

**Feature-level capability coverage** is the objective: for every applicable competitive mechanism in the canonical Forge, find its existing owner, identify the user's job, provide a superior or comparable first-party workflow, and prove it. "Every app" does **not** mean copy vendor source, run every vendor model, import unlicensed weights/media, clone irrelevant business functions, or promise equivalent output quality without trials.

Every proposed new feature must carry:
1. **Forge trace**: canonical donor ID(s), Forge path/commit, observed behavior and date, plus separate recent vendor verification when needed. If wholly original, record ORIGINAL_FIRST_PARTY and why no donor applies.
2. **Owner first**: VALIDATE → REUSE → EXTEND → REFACTOR → CREATE ONLY IF REQUIRED; pin existing SongSpec, ScoreCore, MusicIntent, ProjectRevision, renderer, artifact, sample and cinema owners; no second revision/song/audio authority.
3. **Contract**: input/output, source identity, mutation authority, scope, failure/rights behavior, platform presentation parity, provenance and compatibility.
4. **Test before build**: frozen fixture, expected audio/UI behavior, adversarial negative, non-target preservation, restart and cost/resource limits.
5. **Evidence after build**: exact main/PR SHA, test logs, real WAV decode and identity where audio is claimed, quality/listening assessment where musical quality is claimed; PASS/FAIL/BLOCKED/UNVERIFIED per exact gate.
6. **Promotion**: rightful product-owner acceptance only after independent QA; Forge donor remains a reference, not a runtime dependency. If a donor is rejected/not applicable, retain a reason and evidence, do not silently omit it.

No vendor model subscription, external inference credit, or network access is permitted as a **mandatory** path for core music/video creation. Optional licensed integrations require explicit user authorization, budget and provenance. Commercial clearance is a separate gate.

## User workflow — one project authority, three ways to direct it

**Chat → Guided → Pro** are presentation modes over **one** canonical SongSpec/ProjectRevision/audio-artifact state. No separate chat song store or mobile song store. A user can request an edit verbally, inspect the structured plan, then modify the exact property/section/track. Manual edits must be explainable to S.A.R.A. as real operations. Every action identifies source revision, expected-current revision, target scope, preserved constraints, render attempt, and return artifact; failures preserve prior output.

**Remix core:** Retouch / Rework / Rebuild / Resurrect; what stays vs changes; section lock; voice/lyrics/structure/groove/bass/guitar/DJ/mix controls; audition plan **before** render; revision-bound A/B; selective undo. **Turntakeover:** scratch/skip/beat-juggle/fader/vocal cut controls need physical audible output or clear UNVERIFIED lab labels. **Sample Creator:** import → hash → exact cut → loop → save → reopen; deny unlicensed/protected exports pending rights resolution. **Mobile:** full functional controls in reorganized panels; responsive ≠ reduced; phones need not perform heavyweight inference locally.

## Acceptance ledger — feature may be called shipped only when

- An end user can complete the claimed action in the actual application on both desktop and mobile with the **same backend authority**; accessibility/latency and disabled/failure flows checked.
- The operation produces an actual identified song/project/audio consequence, not a simulated preview, static mockup or chatbot response.
- Version comparison identifies exact changed scope, preserves untouched material and survives process/browser restart.
- Artifact audio is decoded and measured: SHA, container/chunks, codec, sample rate, channels, frame count/duration, peak/DC, silence/dropouts, L/R correlation and edit locality; listening proof separately required for sound quality.
- Rights and voice consent, user/project isolation, cost/net access and failure recovery pass negative tests.
- Source/branch SHA, tests, physical evidence, independent reviewer and rightful owner disposition recorded. Otherwise status is **UNVERIFIED** or **BLOCKED**, not parity PASS.

**Current aggregate parity claim: UNVERIFIED.** The Forge is an input and qualification system; neither catalog size nor M044's bounded vertical means we have Suno-plus quality or the complete app.
